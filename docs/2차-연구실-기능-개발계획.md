# 2차 개발: 연구실용 기능

1차 개발(계정, 내 그룹, 송금 요청·확인, 이메일 초대)에 이어, 연구실에서 쓰기 위한 기능을 단계별로 추가한다.
화면 구성안은 디자인 캔버스(웹 화면 ①~⑧)를 기준으로 한다.

## 원칙 (1차와 동일)

- 기존 기능과 그룹 데이터는 유지한다. 데이터를 지우거나 초기화하지 않는다.
- DB 구조 변경은 추가만 한다(새 표, 새 칸, 새 열거값).
- 권한은 화면뿐 아니라 서버에서 다시 확인한다.
- 계정과 참여자는 이름으로 연결하지 않는다.
- 단계마다 테스트 → 백업 → 배포 → 결과 기록 순서로 진행한다.

## 단계

| 단계 | 내용 | DB 변경 | 상태 |
|---|---|---|---|
| 1 | 역할 바꾸기 (관리자/구성원) | 열거값 1개 추가 | 완료 (2026-11-27) |
| 2 | 내 정산 상세 (보낼 돈/받을 돈의 원인 지출, 이미 받은 돈) | 없음 | 완료 (2026-11-27) |
| 3 | 그룹 설정 + 회비 (기능 켜기/끄기, 금액·주기, 사람별 금액, 쉬는 달, 면제, 계좌 지출) | 표·칸 추가 | 완료 (2026-11-27) |
| 4 | 통계 개편 (회비 있는/없는 그룹, 사람별 먼저 낸 돈과 몫) | 없음 | 완료 (2026-11-27) |
| 이후 | 연구비 카드 결제와 영수증 묶음 제출 | 미정 | 보류 |

정해 둔 사항:

- 회비 계좌로 낸 지출은 개인 정산(누가 누구에게 갚을 돈)에 넣지 않는다. 모두가 모은 돈으로 낸 것이기 때문이다.
- 송금 기록은 사람 사이(예: 한결 → 가은 20,000원)로만 남고 어느 지출을 갚은 것인지는 기록되지 않는다. 그래서 "이미 받은 돈"은 지출별이 아니라 송금 목록으로 보여 준다.

## 진행 기록: 1단계(역할 바꾸기) — 2026-11-27

### 요구사항

- 역할은 관리자와 구성원 두 가지만 둔다. 그룹을 만든 사람이 처음 관리자가 되고, 초대받아 들어온 사람은 구성원이다.
- 관리자만 다른 사람의 역할을 바꿀 수 있다. 관리자는 여러 명일 수 있지만 최소 한 명은 남아야 한다.

### 구현

기존 `Participant.role`(OWNER/MEMBER)을 그대로 쓴다. 화면 이름만 OWNER = 관리자, MEMBER = 구성원이다.

- `src/lib/role-rules.ts`: 역할 변경 규칙(순수 함수 `checkRoleChange`)
  - 계정으로 참여하지 않은 참여자는 역할이 없으므로 거부한다(`NOT_A_MEMBER`).
  - 마지막 관리자를 구성원으로 바꾸는 것은 거부한다(`LAST_OWNER`).
- `src/lib/membership.ts`: `setParticipantRole`
  - 그룹 행을 잠근 트랜잭션(`SELECT … FOR UPDATE`) 안에서 실행한다. 관리자 두 명이 동시에 서로를 내려도 관리자가 0명이 되지 않는다.
  - 잠근 뒤 요청한 사람이 아직 관리자인지 다시 확인한다.
  - 바뀐 경우에만 활동 기록에 `CHANGE_ROLE`을 남긴다(누가, 누구를, 어떤 역할로).
- `src/trpc/routers/groups/members/index.ts`: `groups.members.setRole`
  - `groupOwnerProcedure`라서 관리자가 아니면 403이다.
- 화면 `src/app/groups/[groupId]/members/members.tsx`
  - 관리자에게는 계정으로 참여한 사람마다 역할 선택 칸(관리자/구성원)이 보인다.
  - 구성원에게는 역할이 글자로만 보인다.
  - 아직 참여하지 않은 사람은 "아직 참여 전"으로 표시된다.
  - 목록 아래에 역할 규칙 안내를 넣었다.
- 활동 기록 화면: "가은님이 서영님을 관리자로 바꿨어요." 형식으로 보여 준다.
- DB: `prisma/migrations/20261127000000_add_change_role_activity` — `ActivityType`에 `CHANGE_ROLE` 값 추가(추가만 함).

## 진행 기록: 2단계(내 정산 상세) — 2026-11-27

### 요구사항

- 홈의 "보낼 돈 / 받을 돈"은 합계만 보여 줘서 여러 항목이 있을 때 이유를 알기 어렵다.
- 상세 화면에서 사람별로 어떤 지출 때문에 생긴 돈인지, 이미 주고받은 돈은 얼마인지 보여 준다.

### 계산 방식

`src/lib/my-ledger.ts`의 `getMyLedger(expenses, 나)`가 계산한다(순수 함수).

- 내가 낸 지출: 다른 사람 몫만큼 그 사람이 나에게 갚을 돈이 늘어난다(+).
- 다른 사람이 낸 지출: 내 몫만큼 내가 그 사람에게 갚을 돈이 늘어난다(−).
- 확인된 송금(정산 완료로 생긴 기록)은 "이미 주고받은 돈"으로 따로 모은다. 같은 방식으로 그 사람과의 금액에 반영한다.
- 사람별 금액을 모두 더하면 내 전체 금액(먼저 낸 돈 − 내 몫 + 보낸 송금 − 받은 송금)과 같다. 단위 테스트로 그룹 잔액 계산과 같은지 확인한다.

정산 제안(가장 적은 횟수로 끝내는 송금)은 여러 사람 사이의 금액을 한 번에 정리한다. 그래서 사람별 금액과 실제로 보낼 대상·금액이 다를 수 있다.

- 예: 내가 민서에게 갚을 돈이 있어도, 다른 사람이 민서에게 대신 보내는 것으로 정리되면 나는 보낼 돈이 없다.
- 이럴 때는 화면 위쪽에 "실제로는 이렇게 주고받으면 돼요" 안내를 띄운다. 내 전체 금액은 같다는 설명도 함께 보여 준다.

### 구현

- 서버: `groups.balances.mine` (`src/trpc/routers/groups/balances/mine.procedure.ts`)
  - `groupProcedure`라서 그룹 멤버만 호출할 수 있다.
  - 항상 호출한 사람 본인의 참여자 기준으로 계산한다. 다른 사람 것을 요청할 방법이 없다.
- 화면: `/groups/[groupId]/my-balance` (`src/app/groups/[groupId]/my-balance/`)
  - 계산식 상자: 내가 먼저 낸 돈 − 내 몫 (+ 보낸 송금 − 받은 송금) = 받을 돈/보낼 돈
  - 탭: 내가 보낼 돈 / 내가 받을 돈. 탭의 금액은 홈 카드와 같은 정산 제안 기준이다.
  - 사람별 카드: 지출마다 날짜, 결제한 사람, 금액, 인원, 반영 금액(내 몫 +, 상대 몫 −)을 보여 준다.
  - 사람별 카드 아래: "이미 주고받은 돈"(확인된 송금) 목록
  - 사람별 카드 버튼
    - 보낼 사람에게는 "보냈어요 (확인 요청)"가 보이고, 기존 송금 요청 화면으로 연결된다.
    - 받을 사람이 송금 요청을 보냈다면 "받았는지 확인하기"가 보인다.
    - 이미 요청한 송금이 있으면 "내 송금 요청 보기"가 보인다.
  - 정산이 끝난 사람은 접힌 목록으로 따로 보여 준다.
- 홈과 정산 화면의 "OO님의 정산 현황" 카드에 "상세 항목 보기" 버튼을 추가했다.

### 테스트

- 단위: `src/lib/my-ledger.test.ts`
  - 상계(점심 회식 − 간식)
  - 송금 분리
  - 사람별 합계가 그룹 잔액 계산과 같은지
- E2E: `e2e/my-balance.spec.ts`
  - 홈에서 상세로 이동한다.
  - 계산식 상자를 확인한다.
  - 사람별 지출 항목과 부호를 확인한다.
  - 정산 제안이 사람별 금액과 다를 때 안내가 뜨는지 확인한다.
- 결과
  - 단위 테스트 562개 통과
  - E2E 56개 통과

## 진행 기록: 3단계(그룹 설정 + 회비) — 2026-11-27

### 요구사항

- 회비를 쓰는 그룹만 회비 기능을 켠다. 회비가 필요 없는 그룹은 지금처럼 지출·정산만 쓴다.
- 관리자가 정하는 것
  - 기본 금액
  - 납부일
  - 사람마다 다른 금액
  - 쉬는 달(그룹 전체)
  - 한 사람만 그달 면제
- 구성원이 "회비 냈어요"를 누르면 관리자가 입금을 확인한다.
- 회비 계좌로 낸 지출은 계좌 잔액에서 빠지고, 개인 정산(누가 누구에게 갚을 돈)에는 들어가지 않는다.
- 회비 화면에서 보여 줄 것
  - 계좌 잔액
  - 그달에 걷은 회비 / 회비에서 쓴 돈
  - 누적 합계
  - 달별 납부 현황
  - 회비 납부/회비 사용 필터

### DB 변경 (추가만 함)

`prisma/migrations/20261127100000_add_group_fund`

- `Group`에 칸 추가: `fundEnabled`(기본 false), `fundAmount`, `fundDueDay`, `fundStartMonth`, `fundOpeningBalance`
  - 기존 그룹은 회비가 꺼진 상태 그대로다.
- `Expense.paymentSource`(PERSONAL/FUND, 기본 PERSONAL) 추가. 기존 지출은 모두 PERSONAL이다.
- 새 표
  - `FundMemberAmount`: 사람별 금액
  - `FundRestMonth`: 쉬는 달
  - `FundPayment`: 사람·달마다 하나. 상태는 PENDING / CONFIRMED / REJECTED / EXEMPT
- 기존 데이터를 바꾸거나 지우는 문장은 없다.

### 규칙 (`src/lib/fund-rules.ts`, 순수 함수)

- **달 기준:** 회비는 매달 걷는다. 달은 "YYYY-MM"이고 한국 시간 기준이다. 예를 들어 11월 30일 16시(UTC)는 이미 12월이다.
- **청구 대상:** 계정으로 참여한 구성원만 청구한다. 아직 참여하지 않은 참여자는 청구하지 않는다.
- **"회비 냈어요" 요청 조건**
  - 회비가 켜져 있어야 한다.
  - 시작 달부터 다음 달까지만 요청할 수 있다(다음 달 선납 가능).
  - 쉬는 달, 이미 납부한 달, 확인 대기 중인 달, 면제된 달은 요청할 수 없다.
  - 관리자가 "못 받았어요"(REJECTED)라고 한 뒤에는 다시 요청할 수 있다.
- **계좌 잔액:** 처음 잔액 + 확인된 회비 − 회비 계좌 지출

### 권한 (서버에서 확인)

| 할 수 있는 일 | 누가 |
|---|---|
| 회비 화면 보기 | 그룹 멤버 |
| 회비 냈어요 / 요청 취소 | 본인 것만 (서버가 로그인한 사람의 참여자로 정함) |
| 입금 확인·거절, 납부로 기록, 면제·면제 취소 | 관리자 (`groupOwnerProcedure`) |
| 회비 설정 변경 | 관리자 |
| 회비 계좌로 지출 추가·수정·삭제 | 관리자, 회비가 켜져 있을 때만 |

- 회비 계좌 지출 권한은 `src/trpc/routers/groups/expenses/fund-guard.ts`가 확인한다. 구성원이 API로 직접 요청해도 403이다.
- 회비 관련 변경은 그룹 행을 잠근 트랜잭션 안에서 처리한다.

### 정산에서 회비 지출 제외

- `getBalances`와 `getMyLedger`는 `paymentSource = FUND`인 지출을 건너뛴다.
- 그래서 정산 제안, 내 정산 상세, 송금 확인, 내 그룹 화면의 전체 금액에 회비 지출이 들어가지 않는다.
- 내 그룹 화면의 전체 금액 계산 쿼리에도 `paymentSource`를 추가했다.

### 화면

- **그룹 메뉴**
  - 회비가 켜진 그룹에는 "회비" 탭이 생긴다.
  - 관리자의 "더 보기" 메뉴에는 "회비 설정"이 항상 있다(꺼져 있어도 켤 수 있게).
- **`/groups/[groupId]/fund`**
  - 계좌 잔액 / 그달에 걷은 회비 / 회비에서 쓴 돈 / 누적 카드
  - 달 이동(◀ ▶)
  - 납부 현황: 납부 / 확인 대기 / 미납 / 면제 / 쉬는 달
  - 관리자 버튼: 입금 확인, 못 받았어요, 납부로 기록, 이번 달 면제(이유 입력), 면제 취소
  - 회비 내역(전체 / 회비 납부 / 회비 사용)
- **`/groups/[groupId]/fund/settings`** (관리자)
  - 사용 켜기/끄기
  - 기본 금액, 납부일, 시작 달, 처음 잔액
  - 사람마다 다른 금액(이유 포함)
  - 쉬는 달(연도별 1~12월 선택, 1년 합계 표시)
- **지출 추가**
  - 관리자이고 회비가 켜져 있으면 "돈 출처: 내 돈 / 회비 계좌"를 고를 수 있다.
  - 회비 계좌를 고르면 결제한 사람·나눌 사람 칸을 숨긴다.
  - 회비 화면의 "계좌에서 지출" 버튼은 회비 계좌가 선택된 상태로 열린다.
- **지출 목록:** 회비 지출에 "회비" 표시와 "회비 계좌에서 결제 · 개인 정산 없음"이 붙는다.
- **그룹 홈:** 회비가 켜져 있으면 계좌 잔액과 이번 달 납부 인원 카드가 보인다.

### 함께 고친 보안 문제 (기존 코드)

- 문제: `getExpense`가 그룹을 확인하지 않고 지출 id만으로 찾고 있었다. 그래서 다른 그룹의 멤버가 지출 id를 알면, 자기 그룹 id로 요청해서 그 지출을 조회하거나 삭제할 수 있었다.
- 수정: 그룹 id와 지출 id를 함께 확인하도록 고쳤다. 삭제도 먼저 그룹 안의 지출인지 확인한다.

## 진행 기록: 4단계(통계 개편) — 2026-11-27

### 요구사항 (검증 피드백)

- 통계의 "들어온 돈 / 쓴 돈"이 무엇을 뜻하는지 애매하다.
- 회비 그룹이면 회비로 쓴 돈이 따로 보여야 한다.
- 회비가 없는 그룹은 그룹 총 지출과 사람별로 쓴 돈이 구분돼야 한다.
- "나눠 낸 지출", "내가 결제한 돈 / 내 몫"이라는 말이 이해하기 어렵다.

### 계산 변경 (`src/lib/totals.ts`)

- **회비 계좌 지출이 빠지는 곳**
  - "내가 먼저 낸 돈"(`getTotalActiveUserPaidFor`)
  - "내 몫"(`calculateShare`)
  - 사람별 지출(`getSpendingByParticipant`)
  - 기록한 관리자가 자기 돈으로 낸 것이 아니고, 누구의 몫도 아니기 때문이다.
- **그대로인 것:** 그룹 총 지출, 카테고리별·기간별 통계는 회비 지출을 포함한다. 그룹이 쓴 돈이기 때문이다.
- **새 함수:** `getSpendingBySource`는 지출을 "회비 계좌"와 "한 사람이 먼저 내고 나눈 돈"으로 나눈다.
- **통계 서버(`groups.stats.overview`)**
  - 회비가 켜진 그룹이면 기간 안에 걷은 회비(회비 달 기준)와 지금 계좌 잔액을 함께 돌려준다.
  - 같은 그룹 멤버만 볼 수 있다.

### 화면

- **"돈의 흐름" 카드** (통계 화면, 전체 합계 다음)
  - 회비 그룹
    - "전체 지출 = 회비 계좌 + 먼저 내고 나눈 돈" 한 줄과 막대
    - 회비 계좌 칸: 걷은 회비 / 회비에서 쓴 돈 / 지금 잔액. "따로 갚을 필요 없음" 설명을 붙였다.
    - 먼저 내고 나눈 돈 칸: 그룹이 쓴 돈 / 내가 먼저 낸 돈 / 그중 내 몫 / 받을 돈 또는 보낼 돈. "송금 전 금액"이라는 설명과 내 정산 상세 링크를 붙였다.
  - 회비 없는 그룹: "회비를 쓰지 않는 그룹" 안내와 먼저 내고 나눈 돈 칸만 보인다.
- **사람별 지출 표**
  - 열 이름을 "먼저 낸 돈 / 건수 / 자기 몫 / 차이 (송금 전)"로 바꿨다.
  - 차이는 "+ 받을 돈 / − 보낼 돈"으로 표시한다.
  - 합계 줄을 추가했다.
  - "회비 계좌 지출과 송금은 빼고 계산해요"라는 설명을 붙였다.
- **전체 합계 카드 한국어 문구**
  - "나의 총 지출" → "내가 먼저 낸 돈"
  - "나의 총 부담금" → "내 몫 (내가 써야 할 돈)"
  - "그룹 총 지출액" → "그룹 총 지출액 (회비 계좌 지출 포함)"
